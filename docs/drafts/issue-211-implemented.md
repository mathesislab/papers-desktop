papers-rs follows v3 at faeaf4d now: `file fetch`, `add --fetch-pdf`, `fetch --pdf`, the repair of broken links before a download, and the file of a broken link in the other libraries of the machine (from the `files.json` of their head states, as decision 8 says; papers-rs does not read papers' `file-index/` cache). It passes the 252 offline cases of `design/cases`. On real runs with temporary libraries (a Copernicus DOI, an arXiv id, a bad DOI, `file fetch --missing --supplements` and its dry run, `add --doi --fetch-pdf`, `file check`/`fix` finding files in another library) it gives the same output, library and files as papers.

Papers Desktop uses it when a paper is added: the Add sheet shows the version and the site of the PDF, the link to open in a browser when the download is refused, and the publisher's page when only an accepted manuscript or a preprint was found (point 1 of my previous comment).

One thing found on the way, not about the fetch: a CSL-JSON name with `"family": null` gives `author = {None, Ann}` with `papers add a.json`, and `papers: error: sequence item 0: expected str instance, NoneType found` when the name has nothing else. papers-rs leaves out the null parts.
